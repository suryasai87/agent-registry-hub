# 05: Microsoft Agent 365 interop ("Also registered in")

| | |
|---|---|
| **Researched** | 2026-10-28, public Microsoft Learn pages (dates per row below) and the Databricks SDK 0.157 source. No Microsoft tenant was touched. |
| **Question** | Agent 365 *Connected platforms* syncs Databricks Genie agents into the Microsoft 365 agent registry ([03 §Notable finding](03-ux-benchmark.md)). How can the hub read those registry records and show the Microsoft ID on each agent? |
| **Tags** | **[Doc]** stated in the cited page · **[SDK]** in the Databricks SDK source · **[Inferred]** reasoned, not stated · **[Unverified]** could not confirm |

## Findings

1. **Connected platforms is read-only, manual and one workspace per connection.** Agent 365 signs in to the workspace as a Databricks service principal (OAuth M2M: workspace URL + client id + secret), lists the Genie agents the SP can access and reads their details; with **Can Manage** it also reads conversations for the *Activity* tab, and moves an agent to the trash only when an admin removes it in Agent 365. Synchronisation is **manual** ("Sync agents"), and deletion reconciliation is not guaranteed. [Doc: [Connected platforms](https://learn.microsoft.com/en-us/microsoft-agent-365/admin/connected-platforms), ms.date 2026-10-15; [Connect Databricks Genie](https://learn.microsoft.com/en-us/microsoft-agent-365/admin/connected-platforms-databricks-genie), ms.date 2026-10-15]
2. **What is synced per agent.** Can View: name, description, the workspace's cloud and region. Can Edit: also instructions and data sources (shown as knowledge sources). Synced agents appear under **Agents › All agents**, filterable by **Platform = Databricks Genie**, and in a *Databricks Genie* cluster on the Agent map. The page does not say which Databricks identifier (space id, URL) is kept on the Microsoft record. [Doc: Connect Databricks Genie] → which field carries the Genie space id is **[Unverified]**.
3. **Registry export.** *All agents › Export* produces a CSV ("Export to Excel") of all or filtered agents with "over 30 different items for each agent", e.g. Name, Status, Channel, Date created, Last modified, Publisher, Publisher type, Version, Owner, Description, Platform, Instructions. [Doc: [Agent Registry in the Microsoft 365 admin center](https://learn.microsoft.com/en-us/microsoft-agent-365/admin/agent-registry-overview), ms.date 2026-09-21] The exact header names of the ID and source-URL columns are **[Unverified]**.
4. **Graph API for the registry.** The admin-center page points to the **Package Management API**: `GET https://graph.microsoft.com/v1.0/copilot/admin/catalog/packages` (also `/beta`), paged with an opaque `@odata.nextLink`, permission **CopilotPackages.Read.All** (delegated or application), and it **requires a Microsoft Agent 365 license**; it "works with the AI Admin Role". `$filter` supports `supportedHosts`, `elementTypes`, `lastModifiedDateTime`, `platform` (documented values `Copilot Studio`, `Microsoft 365 Copilot Agent Builder`), `requestStatus`, `requestType`. [Doc: [List Copilot packages](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/admin-settings/package/copilotpackages-list), ms.date 2026-08-27]
5. **Package fields.** `copilotPackage` / `copilotPackageDetail`: `id`, `displayName`, `type` (`external`, `custom`, …), `shortDescription` / `longDescription`, `publisher`, `platform`, `supportedHosts`, `elementTypes`, `manifestId`, `assetId`, `appId`, `agentIdentityId` (the Entra agent identity), `governanceMetadata` (`PromptAgent`, `HostedAgent`, `WorkflowAgent`, `ManagedAgent`, `Unmanaged`, `AIApp`), `lastModifiedDateTime`, usage counters (`activeUsers`, `totalSessions`, …). [Doc: [copilotPackageDetail](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/api/admin-settings/package/resources/copilotpackagedetail), ms.date 2026-08-07] Whether Connected-platform agents are returned by this API (they are third-party records, not Copilot packages) is **[Unverified]**; secondary summaries say they are, the reference page does not.
6. **The older Graph beta `agentRegistry` (`agentInstance`)** is marked for replacement by the Agent 365 registry APIs starting May 2026 ([02 S84](02-oss-mlflow-and-standards.md)). The hub does not use it.
7. **Calling Graph without holding a secret.** A Unity Catalog **HTTP connection** stores the OAuth M2M credential (Entra token endpoint, client id/secret, scope `https://graph.microsoft.com/.default`); `POST /api/2.0/external-function` (`w.serving_endpoints.http_request(connection_name, method, path, headers, json, params)`) makes the call with it and needs `USE CONNECTION`. [SDK: `databricks/sdk/service/serving.py` `http_request`] The app and the sync job therefore only ever know the connection *name*.

## Design (what was built)

| Concern | Choice | Why |
|---|---|---|
| Inputs | (a) optional collector `agent365` paging Graph through the UC connection named in `AGENT365_CONNECTION` (bundle variable `agent365_connection`, default `none` = off); (b) an admin uploads the admin-center export (CSV) or a JSON export / Graph page | (a) needs an Agent 365 license and an Entra app; (b) works today for any tenant admin |
| Scope | only records whose platform / publisher mentions Databricks or Genie, or that contain a Databricks host | the tenant export holds every Copilot agent; the rest is noise and is never stored |
| Matching | identifier first: Genie space id (`…/genie/rooms/<id>` in any column, or an id-like column such as `manifestId` / *Source ID*), serving endpoint, app name (confidence 1.0 / 0.95 / 0.9, halved when the record names another workspace host); else normalised name (exact 0.9, ambiguous-for-Genie 0.8, fuzzy ≤ 0.85) | an id match is unambiguous; names are not |
| Decision | ≥ 0.85 links automatically; weaker matches are *suggested*, the rest *unmatched*; both wait in Governance › Agent 365 for a steward (link / dismiss / reopen, reason required); steward decisions survive re-imports; no assets are created | the registry stays human-governed |
| Storage | `external_registration` (one row per Microsoft record) + `asset_field('also_registered_in')` with `source_label` "Microsoft Agent 365" through `upserts.upsert_source_field` | the same provenance, override, lock-mode and drift rules as every synced field |
| Display | Overview › *At a glance* › Also registered in: registry link, Microsoft ID (copy), platform, how it matched, provenance; stewards unlink (override with reason) or revert | where 03 §5.3 put it |
